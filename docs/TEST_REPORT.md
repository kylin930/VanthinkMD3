## 二、测试方法

本轮不使用“能创建就算通过”的判断方式。`tools/ui_regression.lua` 的做法是：

1. 覆盖服务层函数为固定桩数据，**不发起任何网络请求**，结果可复现；
2. 真实创建 View，真实经 `measure()` / `layout()` 后读取
   `getMeasuredWidth()` / `getMeasuredHeight()` / `getTop()`；
3. 递归遍历视图树查找文本节点，判断文字是否真的被排出了宽度；
4. 用 `MeasureSpec.EXACTLY(320dp)` 的宿主容器测量组件，模拟窄屏；
5. 需要布局完成的断言分布在不同步骤中执行（每步间隔 450ms），避免读到首帧之前的 0 值。

运行：在 NeLuaJ+ 中运行 `tools/ui_regression.lua`，输出 `_ui_regression.txt`。

- 文字颜色取自 `theme.colors()`，未硬编码；回归脚本统计 28 个文字样本，
  逐项比对文字色与最近不透明背景的亮度差，**无同色 / 低对比度文字**。
- 当前运行模式：system（真机为浅色）。深色模式对比度断言**未在本轮复跑**，
  需在真机切换为深色后再次运行 `tools/ui_regression.lua`。
- 摘要卡片、徽标、图表的颜色全部沿用 MD3 角色（primary / tertiary / secondary /
  surfaceContainer*），未引入新色值。

## 八、未验证 / 遗留项

1. **深色模式对比度未复跑**（见第 6 节）。
2. **真实账号数据链路未验证**。回归脚本使用固定桩数据；真实接口返回的字段差异
   （超长作业名、超大数值、空字段）可能带来排版问题，已用 `maxLines` + weight 兜底，
   但仍建议用真实账号复核一次。
3. **平板 / 横屏无专属布局**：仍单列拉伸；`isCompactWidth()` 只在 < 360dp 时改单列。
4. **Auth 迁移真实二维码未复测**：验证的是失败态正文可见性；真实生成需要
   登录态与第三方服务可用。
5. **语音练习、摄像头扫码** 仍不在实现范围（原因见 `README.md` 已知限制）。
