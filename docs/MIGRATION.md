## 四、作业操作（重点：合规性修正）

| 功能 | 原项目实现 | 本版本 | 说明 |
| --- | --- | --- | --- |
| 单题提交完成 | 用户手填「通关时间（秒）」→ `saveScore` | ✅ | 保留，增加耗时范围校验（1~86400 秒） |
| 「一键完成」（Beta） | 遍历非语音题，**用排行榜第一名耗时 + 随机 1~5 秒**作为 `spend_time`，自动批量提交 | ❌ | **已移除**，见下方说明 |
| 「多选练习」批量执行 | 最多选 30 个作业，同上一键完成逻辑，加 3~6 秒随机等待「模拟真人」，用 `self.accuracy` 阈值（达标 100 / 普通 80）跳过已完成 | ❌ | **已移除**，同上 |
| 成绩/准确率 | `scores=0`、`correct_rate=0`、`wrong_exercises=[]` | ✅ | 与原项目一致，不伪造 |
| 语音题跳过逻辑 | 名称含「读」且 ≠「阅读理解」 | ✅ | 迁移为 `homeworkService.isVoicePractice` 用于 UI 标识与提示 |

### 为什么移除批量自动做题

原实现（`index_uF4aI7iR.js:203-247`、`:339-627`）的核心逻辑是：

1. 查询排行榜取第一名耗时 `original`；
2. 提交 `original + random(1..5)` 秒作为自己的 `spend_time`；
3. 加 `random(3000..6000)` 毫秒随机等待，伪装真人操作节奏；
4. 对多份作业循环执行。

这属于**伪造学习记录**：不仅把不存在的练习完成写进服务端，还会因为耗时极短而污染
**其他同学可见的排行榜**。同时违反该平台对学生练习数据的真实性预期。

本版本的处理：

- **不提供**任何形式的自动提交、批量代刷、随机耗时生成；
- **保留业务入口**：「记录练习完成」，要求用户输入自己实际的练习耗时，二次确认，
  界面明确说明「只能用于你确实完成过本次练习的情况」；
- 不伪造 `accuracy` / `scores` / `stars`。

## 十二、修正的原项目缺陷清单

| 缺陷 | 原实现 | 本版本 |
| --- | --- | --- |
| 二维码生成实际不可用 | `qrcode.min.js` 未引入，`typeof QRCode !== 'function'` 直接 return | 纯 Lua 编码器，已通过 ISO 标准表与解码交叉验证 |
| 批量已读提交历史所有 id | `noticeList` 翻页不清空 | 只提交当前未读项 |
| Token 明文存储 | `localStorage` | Keystore AES/GCM |
| Token 失效无处理 | 只报 HTTP 错误 | 识别 44，统一重新登录 |
| 主题监听重复注册 | 同一元素绑两次 | 无重复监听 |
| Ciallo 双音源叠音 | 本地 aac + 远程 aac 同时播放 | 未迁移该功能 |
| 语音题 ReferenceError | 调用未定义的 `doReadGame` | 明确提示，不抛异常 |
| 一键完成/批量代刷伪造数据 | 随机耗时 + 随机等待 | 移除，改为真实录入 |
| 关闭对话框不停轮询 | 只在 `beforeunload` 停止 | 页面隐藏即停止 |
